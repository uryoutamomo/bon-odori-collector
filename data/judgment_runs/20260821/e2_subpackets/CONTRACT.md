# E2 同一性判定タスク（盆助）

X投稿から作られた「盆踊りイベントの登録提案」について、**それが既存のどれと同じものか**だけを判定します。

## 0. あなたが答えるのは3つの同一性だけです

イベント名・開催日・会場名を**書かないでください**。それらは既に提案の中にあり、機械が取ります。
あなたが答えるのは次の3つと、その理由だけです。

- `occurrence_match` … この提案は「既存の開催回候補」のどれと同じ回か。どれとも違うなら `"none"`
- `series_match` … どの系列（毎年続いている同じ行事）に属するか。どれとも違うなら `"none"`
- `venue_match` … 会場は「既存の会場候補」のどれか。どれとも違うなら `"none"`

**「どれとも違う」は必ず文字列 `"none"`** にしてください。空文字・null・省略はすべて拒否されます。

## 1. 判定の考え方

### occurrence_match（開催回）

同じ行事の**同じ年の同じ開催**を指しているときだけ一致とします。

- 候補の `event_year` が提案の年と違うなら、それは**別の回**です。`"none"` にしてください。
  例: 提案が2026年で候補が2025年なら、同じ行事でも回としては別。この場合 `occurrence_match` は `"none"`、
  ただし `series_match` にはその候補の `series_id` を入れます（同じ系列の去年の回だから）
- 名前が「第16回」「第17回」のように回数だけ違うのは、**同じ系列の別の回**です
- 日付が大きく違う（別の月）なら別の行事の可能性が高いので、慎重に

### series_match（系列）

- `occurrence_match` に具体的なIDを入れたなら、`series_match` は**必ずその候補の `series_id` と同じ**にしてください。
  食い違うと機械に拒否されます
- `occurrence_match` が `"none"` でも、候補の中に同じ行事の別の年の回があるなら、その `series_id` を入れます
- 「既存の系列候補」が空でも、開催回候補の `series_id` は使えます
- どの系列にも属さない新しい行事なら `"none"`

### venue_match（会場）

- 表記が違っても**同じ場所を指しているなら一致**にしてよいです（「浜松町駅北口広場」と「ハマサイト前広場」など、
  同じ敷地だと読めるもの）。ただし確信が持てないときは `"none"` のほうが安全です
- **区が違う会場は別物**です。名前が似ていても一致させないでください
- 「◯◯小学校」「◯◯公園」は全国に同名が多いので、区・住所を必ず確認してください

## 2. 行為（`requested_action`）

- `accept` … 上の3つを答えられた（`"none"` を含んでよい）。通常はこれです
- `reject` … この提案は登録すべきでない（盆踊りではない、明らかな誤りなど）
- `hold_for_user` … 情報が足りず、人の判断が要る

**`"none"` だからといって `hold_for_user` にしないでください。** 新規かどうかで人を挟むかは機械が決めます。
あなたは素直に `accept` ＋ `"none"` を返してください。

## 3. 出力形式

指定されたパスに、次の形のJSONを1ファイル書いてください。入力の全件について1件ずつ、漏れなく。

```json
{
  "decisions": [
    {
      "packet_id": "packet_280916ba0447c885",
      "requested_action": "accept",
      "occurrence_match": "none",
      "series_match": "ser_f7b58eebe46b8e99",
      "venue_match": "none",
      "reason_detail": "第17回は2026年の新しい回。候補の第16回（2025年）と同じ系列。会場は浜松町駅北口広場で、候補の会場はいずれも別の区なので該当なし"
    }
  ]
}
```

- `packet_id` は入力のものを**そのままコピー**してください（照合に使います）
- `reason_detail` は日本語1〜2文。**なぜその同一性にしたか**を書いてください
- IDは候補リストに載っているものだけ使えます。**存在しないIDを書くと機械に拒否されます**

## 4. 守ってほしいこと

- Web検索・WebFetchは使わないでください。パケットの中身だけで判断します
- メモリファイル（~/.claude/.../memory/）は読まないでください
- イベント名・日付・会場名を出力に含めないでください（同一性だけが仕事です）

終わったら、書き出したパスと、`accept`/`reject`/`hold_for_user` の件数、`"none"` の内訳だけを短く報告してください。

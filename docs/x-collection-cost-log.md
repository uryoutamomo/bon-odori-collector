# X収集の費用ログ

内田さんの指示（2026-08-12）「費用の変化についても記録しておいて欲しい」に基づく台帳。
**改善を入れるたびに、その前後の実測をここへ追記する。**

計測の正本は `data/x_budget.json`（日次合計）だが、これは内訳を持たない。
経路別の記録は `data/x_cost_ledger.json`（`collection_support/x_cost_ledger.py`）が持つ。
**2026-08-12〜15 はこの台帳が `collect.yml` の `git add` から漏れていて1件も残らなかった**ので、
その期間の内訳は復元できない（2026-08-16 のPRで修正、INV-COL-007）。
台帳に無い期間は GitHub Actions のログから手で拾ってここへ書く。**Actionsのログは保存期間を過ぎると
消えるため、拾った数字はその都度この文書に残すこと。**

料金は twitterapi.io の $0.15/1000件 ＝ 1件 $0.00015。
予算ガードは日次 $3.0 / 月次 $25.0（`x_queries.json` の `budget`）。

### ①コホート窓短縮の実測（2026-08-12〜15）

`data/x_budget.json` の日次合計。**$0.71 前後から $0.47 前後へ、4日とも安定して下がった。**

| 日 | 合計 | ベースライン比 |
|---|---|---|
| 2026-08-12 | $0.4704 | −34% |
| 2026-08-13 | $0.4770 | −33% |
| 2026-08-14 | $0.4797 | −33% |
| 2026-08-15 | $0.4877 | −32% |

**⚠️ 経路別の内訳は取れていない。** `data/x_cost_ledger.json` は 2026-08-12 に作ったが、
`collect.yml` の `git add` に入れ忘れていたため、**4日ぶんの記録が毎回ワークスペースと一緒に消えていた**
（台帳は 8/11 の手入力ベースライン4件のまま）。本PRで `git add` を追加したので、
次回runから経路別・クエリ別に残る。この穴は INV-COL-007 として仕様に書いた。

したがって上の $0.47 のうち search がいくらかは**推定でしかない**。
ベースラインの search $0.264 と whitelist $0.1176 が変わっていないと仮定すれば、
search は全体の **約54%** を占めていることになる（37%→54%。分母が減ったため割合は上がった）。

### ②検索クエリの watermark（本PR）

**何に払っていたか。** ベースライン日の search は 1,760件取得して voices 採用 660件（37.5%）だった。
意味による除外は 2026-08-15 に廃止済みなので、**採用されなかった1,100件はすべて「前日までに読んだ投稿」である。**
毎回1ページ目から読み直し、既読URLを保存の段で捨てていたためで、捨てていたのは保存であって課金ではない。

**やったこと。** クエリごとに `since_time` を `data/x_query_watermarks.json` へ持ち、次回はその先だけを読む。
名簿の直読みが前からやっていたことを、検索にも入れただけである。加えて、新規0件のページに達したら
そのクエリを打ち切る（`queryType=Latest` は新しい順なので、そこから先は既読の領域）。

**削減の見込みは全額ではない。** ページ上限（8ページ）に当たっているクエリは、
`since_time` を入れても「窓の中の最新160件」を読むだけで取得件数が変わらない。
ベースライン日に満杯だったのは `q-base`（156件）で、ここは減らない。
減るのは上限まで届いていないクエリ（`q-report` 122件、`q-future-schedule` 96件、`q-poster-flyer` 43件ほか）で、
そこに含まれる既読分が落ちる。**$0.264 のうちどこまで落ちるかは、次回runの台帳を見るまで分からない。**

**取りこぼしを増やさないための約束。** 読み切れずページ上限で切れたクエリは窓を進めない（INV-COL-006）。
進めると、その時間帯は二度と検索対象にならない。据え置いても費用は増えない——
ページ上限が費用の天井なので読む量は変わらず、投稿が少ない日に窓が追いつく。

**次回runで見ること。** ①search の費用（下がったか）②voices 採用件数（**維持されているか**）
③`data/x_query_watermarks.json` が11本ぶん記録されたか ④ページ上限で切れたクエリがどれか
（台帳の `note` に `completed:False` として残る）。

残りの順序は 15節のとおり、③名簿の頻度分け（$0.1176）。

# X収集の費用ログ

内田さんの指示（2026-08-12）「費用の変化についても記録しておいて欲しい」に基づく台帳。
**改善を入れるたびに、その前後の実測をここへ追記する。**

計測の正本は `data/x_budget.json`（日次合計）だが、これは内訳を持たない。
経路別の記録は S2 でおとが `collect.py` に入れる予定で、それが動き出すまでは
GitHub Actions のログから手で拾ってここへ書く。**Actionsのログは保存期間を過ぎると
消えるため、拾った数字はその都度この文書に残すこと。**

料金は twitterapi.io の $0.15/1000件 ＝ 1件 $0.00015。
予算ガードは日次 $3.0 / 月次 $25.0（`x_queries.json` の `budget`）。

同日の内訳の内訳（ログから読めた範囲）：

  `q-future-schedule` 96件、`q-poster-flyer` 43件ほか。**毎回1ページ目から読み直すため
  既読分にも課金されている**（S2の watermark で改善予定）
- whitelist は 20人×14バッチ、1バッチあたり最大3ページ
- 証拠掘りは窓 `2026-07-28 → 2026-08-11` を50人分

### 月次の推移

| 月 | 合計 | 稼働日数 | 1日平均 |

### 費用対効果（直近30日の実測・2026-07-13〜08-11）

| 経路 | 採用した投稿 | うち有用 | 有用の定義 |
|---|---|---|---|
| 検索クエリ | 14,407件 | 5,237件（36%） | 盆踊り語＋東京、または曲名の言及 |
| whitelist | 7,643件 | 524件（7%） | 同上 |

ただし**この率で経路の優劣を判断してはいけない**。検索は「盆踊り」等の語で引くので
率が高くなるのは当然で、whitelist はその人の全投稿を読むので低くなる。

whitelist の固有価値は「**検索クエリでは原理的に拾えない投稿**」にある。
検索語に一致しないのに有用だったものは30日で **125件（1日4.2件）**。中身は
「64'以前の東京音頭が踊れたのが嬉しかった」「〆は東京音頭か炭坑節というのが以前は
多かったが最近はダンシングヒーロー」「江州音頭のアレンジです」といった、
盆踊りコミュニティの会話だった。**費用を削るときはこの固有価値を壊さないこと。**

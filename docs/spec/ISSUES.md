# 仕様書監査で確認した問題点

2026-08-16 に、おと（Codex）が `docs/spec/` と実装・workflow・テストを突き合わせて確認した問題を記録する。
ここは「すでに分かっている穴」を隠さず、修正順と残作業を追跡するための台帳である。

状態は `未着手` / `対応中` / `一部対応` / `対応済み` で表す。`対応済み` は、実装・仕様・テストが揃い、
残る制約が仕様に明記された状態を指す。

## 仕様書・仕様基盤の問題

| ID | 重要度 | 状態 | 問題 | 何が困るか | 次の対応 |
|---|---|---|---|---|---|
| SPEC-001 | 重大 | 未着手 | `impact` が変更対象の下流ではなく、`depends_on` の上流へたどっている | 収集の変更から判断・レビュー・公開への影響が出ず、変更前の警告として不十分 | 逆依存を構築し、直接所有＋下流影響を表示する |

| SPEC-003 | 高 | 未着手 | 「コードと仕様を同じPRで更新」の原則をCIが強制していない | `updated_for` と本文が実装変更から遅れても、緑のままmergeできる | ownedコード変更時の仕様差分または明示的確認を必須にする |

### SPEC-005 で確認済みの矛盾

- [収集](L1/01-collection.md)では意味的な除外を廃止済みだが、[判断](L1/02-judgment.md)・[用語集](L1/11-glossary.md)では有効な入力として残る。
- [配信](L1/06-delivery.md)はメールテストを列挙する一方、未解決欄で「テストが1件も無い」としていた（APP-001対応時に解消済み）。
- [公開JSON](L2/public-json.md)は疎構造テストを列挙する一方、未解決欄で「テストが無い」としている。
- [マスタ](L1/04-master.md)は変更種別を5種類とするが、実装は `create_event_series` を含む6種類である。
- [YouTube](L1/09-youtube.md)が、削除済みの `legacy/notion_writes/` を現存する経路として参照している。
- [L0](README.md)のPythonファイル数・行数は削除前の値である。

## 盆助本体に見つかった、仕様と結びつく問題

| ID | 重要度 | 状態 | 問題 | 次の対応 |
|---|---|---|---|---|
| APP-001 | 重大 | 対応済み | 旧方式ではSMTP送信成功後、削除commit前に失敗すると同じドラフトを自動再送した。宛先の一部もソースへ直書きされていた | 2026-08-16に送信前claim、曖昧状態の自動再送禁止、全宛先のSecret化、監視とテスト更新を実施 |
| APP-002 | 重大 | 未着手 | 公開イベントに安定IDがなく、`name + venue` が同一性を担う | 公開用 `event_id` / `occurrence_id` を追加し、移行期間を設ける |
| APP-003 | 高 | 未着手 | 会場フィード失敗、YouTubeクォータ枯渇、用語集空データなどがworkflow成功として終わり得る | 最終成功時刻・件数急減・進捗率の監視と通知を追加する |
| APP-004 | 中 | 未着手 | 曲目レビュー、YouTubeセットリスト、チャンネル名簿、会場ジオコーダーなどに停止・手動運用が残る | 提供中／停止中を明示し、復旧か正式廃止を決める |
| APP-005 | 中 | 未着手 | RDB・凍結JSON・旧Notion経路・一回限りスクリプトが混在し、正本と経路の寿命が分かりにくい | active / manual / deprecated / dead と削除予定を各仕様へ持たせる |

`APP-001` は [配信仕様](L1/06-delivery.md) の修正と同時に対応した。
公開JSONのcollector側379件・site側370件という記録はローカルスナップショットの差であり、
現在の本番サイトにも同じ差があることまでは確認していない。

## 対応履歴

### 2026-08-16 APP-001 対応済み

- SMTP送信前に `pending_mail.json` を `sending_mail.json` へ移し、commit・pushできたrunだけが送るようにした。
- `sending_mail.json` が残る曖昧状態は定時workflow・watchdogとも自動再送せず、赤いworkflowとして検出する。
- ソース内の既定宛先・常時追加宛先を削除し、既存2宛先をGitHub Secret `MAIL_TO`へ値を表示せず移行した。
- pushによる自動送信は `main` ブランチだけに限定した。
- 配信テストを19件へ拡充し、全体で1607件と158 subtestsが通ることを確認した。
- SMTPには冪等キーがないため、曖昧状態の解消はGmail送信済みの人手確認を必要とする。この制約は[配信仕様](L1/06-delivery.md)へ明記した。

# X盆踊ラー再評価 v1 仕様（2026-08-11）

内田さんの指示「Xの盆踊ラーを再評価したい。X収集のコストにも情報の精度にも関わる。
これからのイベントを教えてくれる盆踊ラーも貴重だが、盆踊りに関する意見も盆助のコンテンツに役立つ」
を受けて、こと（Claude Code）が実データで診断し、評価軸の作り直しを設計したもの。

内田さんの方針決定（2026-08-11）は次の3点。

1. 評価軸そのものを作り直す（名簿の手直しだけで済ませない）
2. 告知の名簿とコンテンツの名簿は**分ける**。ただし**両方に載る盆踊ラーがいることを前提**にする
3. 23区外で活動する盆踊ラーも**人は残す**。外すのは地域ニュースbotだけ

---

## 1. なぜ作り直すのか（診断）

計測に使ったのは 2026-08-11 07:47 生成の `data/x_account_scores.json`（13,175アカウント）、
同日 07:35 の本番 collect 実行ログ、`data/x_gap_candidates.json` と
`data/x_review_lanes.json` の main 全リビジョン、ローカル `data/voices.json`（〜07-27）による。

### 1-1. 有用度スコアが満点に張り付き、選抜が名前順になっている

`_x_account_usefulness_score()` はランク別の基礎点（S=90）に各種ボーナスを足して
`min(100, ...)` で刈るため、**Sランクの上位260件がすべて 100.0 に張り付いている**。
`_load_trusted_score_accounts()` はこのスコアの降順→ハンドル名昇順で上位250件を採るので、
**同点260件のうち10件が、実力ではなくハンドルの頭文字だけを理由に落選している**。
実際の切れ目は `@yan_su_su`（採用）と `@yoritaka11`（落選）の間で、落選側には
`@yuaitiiki`（世田谷の町会盆踊りを継続的に告知・直近30日の未来日告知8件）や
`@znafg`（下北沢の盆踊りを詳述）が含まれる。

### 1-2. 読んでいる250人の4割は、23区の盆踊りを一度も書いていない

選抜250のうち本文が3件以上あるのは212件。そのうち **85件（40%）は「盆踊り関連かつ23区」の
投稿がゼロ**。上位を占めるのは全国イベントまとめbotと他地域のニュース
（`@matsudotsushin` 松戸・`@ichikawa_news` 市川・`@goguynet_osaka` 茨木・`@kobejournal` 神戸・
`@mypl_fukushima` 福島）。未来日を大量に含む投稿を高く評価する現行式が、
告知botを構造的に上位へ押し上げている。

### 1-3. 出口へ届いた投稿の書き手は、大半が「読みに行っていない人」

x_gap候補・レビューレーンに実際に載った投稿の書き手39アカウントのうち、
**選抜250に入っていたのは15件だけ**。残り24件は検索クエリで偶然拾えたもので、
入二町会 `@iri2choukai`（公式の新規イベント2件）、神田観光協会 `@kandakankou`、
蛇窪神社、品川観光協会、深川くらし `@fukagawakurashi` といった町会・神社・地域団体が並ぶ。
これらは投稿数が少ない（台帳上5〜12件）ため、量を前提とした現行スコアでは上位に来られない。

### 1-4. コストの実態（2026-08-11 の本番実行）

| 工程 | 1日あたり | 内容 |
|---|---|---|
| 検索クエリ11本 | $0.264 | voices 660件採用 |
| whitelist（268アカウントの直読み） | $0.118 | 506件採用 |
| 証拠掘り（固定コホート50人×2週間） | $0.330 | 389断片 |

合計 $0.7146/日。8月は11日で $7.34、この調子で月$20（上限$25）。
**読む人数を増やす余地はほぼ無く、入れ替えるしかない。**
また証拠掘りのコホート50人は 2026-06-10 に固定されたきりで、
**13人は直近30日に未来日の告知を1件も出していない**（うち2人は投稿自体ゼロ）。

## 2. 作るもの

### 2-1. 名簿を2本に分ける

| 名簿 | ファイル | 用途 | 規模の目安 |
|---|---|---|---|
| 告知名簿 | `data/x_roster_announce.json` | イベント告知の収集対象（whitelist直読み・証拠掘りコホートの母集団） | 180 |
| 意見名簿 | `data/x_roster_voice.json` | 盆踊りへの意見・体験の収集対象（記事やニュースの素材源） | 60 |

**同じハンドルが両方に載ってよい**（試作では33件が重複）。
whitelist へ渡すときは和集合を取り、重複は1回だけ読む。
既存の `data/x_collection_roster.json`（手動名簿67件）は**そのまま正本として残す**。

### 2-2. スコアを2本立てにする

いずれも `data/x_account_scores.json` の各行へ `announce_score` / `voice_score` として
追加する。既存の `usefulness_score` は互換のため残すが、名簿の選抜には使わない。

#### 告知力 announce_score

```
s  = min(10, 10 * log1p(recent_future_schedule_posts) / log1p(20))
s += 14 * bon23_ratio_smoothed
s -= 5 * max(0, listy_ratio_smoothed - 0.30)
if bon23_count == 0 and posts_with_text >= 5:   s = min(s, 8.0)
s += 5 * min(gap_credits, 3)
if is_area_bot:                                  s -= 15
```

- `recent_future_schedule_posts` は既存の集計値をそのまま使う
- `bon23_ratio` は本文が「盆踊り関連かつ東京23区」である割合（後述の判定）
- `listy_ratio` は行頭日付3行以上または8行以上の投稿の割合（まとめ投稿の指標）
- `gap_credits` は x_gap候補・レビューレーンに採用された回数（**新規に台帳へ持つ**）
- 23区の実績が本文で確認できないアカウントは、告知量だけでは8点を超えられない
  （道頓堀・松戸などが上位に来ないための上限）

#### コンテンツ力 voice_score

```
前提: 本文のある投稿が3件以上（未満は 0.0）
s  = 10 * opinion_ratio * (0.5 + 0.5 * experience_ratio)
s +=  6 * detail_ratio      # 曲目・櫓・太鼓・練習会などの具体語
s +=  3 * media_ratio       # 写真つき＝一次体験
s +=  4 * min(avg_len / 150, 1.0)
s +=  8 * bon23_ratio_smoothed
s -=  8 * listy_ratio_smoothed
s +=  3 * min(distinct_post_days / 10, 1.0)   # 継続して書いているか
if recent_posts_seen == 0:  s -= 3
if is_area_bot:             s -= 10
```

#### 比率は必ず件数で縮約する（重要）

`ratio = (count + 5 * base) / (n + 5)` の形で全体平均へ引き戻す。
これを入れないと**投稿1件のアカウントが全比率1.00で満点になる**（試作v1で実際に起きた）。
`base` は 意見0.35 / 体験0.20 / 具体0.30 / 写真0.30 / まとめ0.15 / 23区盆踊り0.10。

### 「書き手が人かどうか」を一人称で測ってはいけない（2026-08-11 内田さん指摘）

初版は `first_person_ratio`（私・僕・自分…）で「人が書いた文章か」を測る設計だったが、
内田さんから「日本語では一人称はほとんど省略されるが大丈夫か」と指摘を受けて実測したところ、
**その通りで使い物にならなかった**。

- X投稿10,630件のうち一人称を含むのは **9.0%** だけ
- 体験を述べた投稿1,875件のうち一人称も書いているのは265件（14.1%）＝
  **体験談の86%を取り逃す**
- 決定的なのは、**手動名簿の「優先／通常」29人のうち10人が一人称ゼロ**だったこと。
  `@kaz0045`（投稿46件・体験16件）や `@hideshanbonbon`（投稿19件・体験11件）は
  明らかに本物の書き手だが、一人称を一度も使っていない

代わりに **体験表現** を使う。語彙は `x_queries.json` の `experience_keywords` を正本とし
（コードに直書きしない）、体験ではない曲目系5語（曲目表・曲順・プログラム・演目・曲目発表）は
体験判定から除く。実測の被覆は既存語彙のままで13.7%、活用形を足すと23.5%。

分離力も体験表現の方が高い。投稿4件以上で比べると次のとおり。

| 指標 | 地域bot27件 | 手動名簿の人29件 | 差 |
|---|---|---|---|
| 一人称 | 0.00 | 0.09 | 0.09 |
| 体験表現（語彙拡張） | 0.12 | 0.24 | 0.12 |
| URL率 | 0.97 | 0.58 | −0.39 |

したがって `first_person_ratio` は台帳から落とし、`experience_ratio` に置き換える。
bot判定の条件も `first_person_ratio <= 0.15` から `experience_ratio <= 0.15` にする
（bot平均0.12・人0.24なのでこの位置で分かれる）。
なお bot と人をいちばん強く分けるのは URL率（0.97 対 0.58）で、既定の 0.8 は妥当。

### 2-3. 地域ニュースbotの判定

```
posts_with_text >= 4
かつ url_ratio >= 0.8         # ほぼ全投稿にリンク
かつ experience_ratio <= 0.15 # 行った・踊った・楽しかった等の体験表現が出てこない
かつ bon23_count == 0          # 23区の盆踊りを書いたことがない
かつ (outside_ratio >= 0.4 または bon_ratio < 0.5)
```

試作では27件が該当し、うち17件が現行の選抜250に入っていた
（`@kobejournal`・`@matsudotsushin`・`@ichikawa_news`・`@mypl_fukushima`・`@shonanjincom`・
`@santama_genjin`・`@ilias0322`・`@bondbont` ほか）。

**他県の盆踊りにも行く個人は bot ではない。** 例えば `@5khfya5pjksggov` は他県の櫓の
組み方まで論評する良質な書き手で、`experience_ratio` と `bon_ratio` が高いので
上の条件に当たらない。内田さんの「人は残し、地域botだけ外す」はこの条件で表現している。

### 2-4. 手動名簿の判断は機械が覆さない

`data/x_collection_roster.json` で `manual_status` が **優先 / 通常** のアカウントは、
スコアに関わらず両名簿の和集合へ必ず含める（試作では32件）。
`休止` は逆に、スコアが高くても入れない。

理由は、人が下した判断をシステムが覚えず毎日蒸し返す問題を繰り返さないため
（ゐの市の一件と同じ構図）。試作v2では `@niinobon_uta`（優先指定）や `@wadaikoch` が
機械判定で落ちており、この保護が無いと人の決定が静かに巻き戻る。

### 2-5. タイブレークを実力で行う

名簿の切り出しは `announce_score` / `voice_score` の降順。同点の場合は
`(gap_credits, bon23_count, recent_posts_seen)` の順に見て、それでも同じならハンドル名。
**ハンドル名を第一のタイブレークにしない。**

### 2-6. 証拠掘りコホートの再選定

`data/x_event_evidence_cohort.json`（2026-06-10 固定・50件）を、
**告知名簿の上位50**で組み直す。selection 名は
`announce_score_top_50_excluding_paused` とし、`selected_at` を更新する。

⚠️ `data/x_event_evidence_state.json` の `selected_handles` / `selection_id` を変更すると
コホート変更扱いで走査状態が破棄される。**コホート差し替えは走査窓が現在に追いついている
タイミングで行い、切り替え後に窓が未来へ飛んでいないことを確認する**（PR #120 の再発防止）。

## 3. 23区判定の落とし穴（negative test にすること）

1. **政令市の同名区**。「名古屋市北区」「札幌市中央区」「大阪市港区」は23区ではない。
   区名の裸マッチより先に `札幌市|仙台市|さいたま市|千葉市|横浜市|川崎市|相模原市|新潟市|
   静岡市|浜松市|名古屋市|京都市|大阪市|堺市|神戸市|岡山市|広島市|北九州市|福岡市|熊本市`
   を打ち消しに使う。試作v2では `@comcom_e_shiga`（名古屋市北区の学区だより）が
   「23区の盆踊り9件」と誤カウントされた
2. 逆に**区名の裸表記は拾う**必要がある。「#世田谷」「練馬の盆踊り」は23区。
   政令市ガードを先に置けば両立できる（試作v3で確認）
3. **「東京音頭」を東京の地名として数えない**（既存 `東京(?=市|区|駅|[・、])` の先読みを踏襲）
4. **同名会場**。「住吉」は神戸市東灘区にもある。会場名だけで23区と決めない

## 3-2. テストは「その仕掛けを外したら落ちる」ことまで確かめる

PR #174 のレビューで、**書いたテストのうち2本が、守りたい仕掛けを外しても通っていた**。

- 縮約（`(count + 5*base)/(n + 5)`）を素の `count/n` に戻しても4件とも通過した。
  比率が同じ2アカウントを比べていたため、縮約の有無で差がつかなかった
- bot判定の人物保護条件を `True` に潰しても通過した。テストの「他県へ行く個人」は
  「兵庫の盆踊り」という本文で、`兵庫県` ではないため都外判定に掛からず、
  別の条件（盆踊り率）で救われていた

政令市ガードのテストだけは、外すと `bon23_count` が 0→1 になって正しく落ちた。

したがって各negative testは、**守りたい行を1行だけ潰した状態で実際に落ちること**を
確認してから完了とする。比率の縮約のように、統合テストでは差が出にくいものは
`_x_smoothed_ratio(3, 3, 0.35) < 1.0` のような直接の単体テストにする。

## 4. 移行の段取り

各段は前段の実測を確認してから進める。

| 段 | 内容 | 完了条件 |
|---|---|---|
| S1 | スコア2本と bot 判定を `collect.py` に実装し、台帳へ書き出すだけ（名簿は従来のまま） | 台帳に `announce_score`/`voice_score`/`is_area_bot`/`gap_credits` が入り、既存の収集挙動が1件も変わらないこと |
| S2 | 名簿2本を生成するスクリプト新設（既定 dry-run） | 生成された名簿と現行250の差分レポートが出ること。実際の収集対象は変えない |
| S3 | whitelist の供給元を新名簿の和集合へ切り替え | 収集アカウント数・日次コスト・voices採用件数を前後で比較。**23区の盆踊り投稿の採用数が減っていないこと** |
| S4 | 証拠掘りコホートを差し替え | 走査窓が未来へ飛んでいないこと。断片検出数が前週比で落ちていないこと |

S3 の切り替えでは、試作の見立てで **外す106件・入れる88件・残る144件**（新名簿232人）。
whitelist のコスト削減は $0.118 → 約$0.10/日 と小さい。**この作業の主目的はコスト削減ではなく、
同じ予算で読む相手を入れ替えること**である点を、実装時も見失わないようにする。

## 8. 直した4か所

### 8-1. 中止・変更の速報を評価していなかった

宇佐美さんの「上野の彩之會さんの盆踊り中止、豊洲盆踊り中止、西久保八幡神社も中止だね」
という投稿は**未来の日付を含まない**ため、告知力スコアが素通りしていた。
盆踊り関連で中止・変更に触れた投稿は実データで1,120件（うち23区166件）ある。

```
announce += min(5.0, 1.2 * change_count)
change_count = 盆踊り語 かつ 23区 かつ (中止|順延|延期|荒天|規模縮小|時間変更|
                取り止め|とりやめ|見合わせ) を含む投稿数
```

これで宇佐美さんは告知31位→14位。終わった行事や中止の行事が「開催予定」のまま
公開され続ける問題（`transition_ended_occurrences.py` の背景）に直結する軸なので、
単なる加点ではなく**運用上の要**として扱う。

### 8-2. 曲名・会場名・行事名をマスタで引いていなかった

初版は「炭坑節・東京音頭・ダンシングヒーロー」等を正規表現に直書きしていた。
宇佐美さんが書く「竹芝絵巻」「高輪ゲートウェイ夢拍子」「春駒」「猫の手」は拾えない。

- **曲**は `songs.canonical_title` ＋ `song_aliases.alias`（3文字以上）で引く。
  具体性の判定被覆が 16.1% → 23.7%
- **会場**は `venues` のうち `area`/`address` が23区のもの367件。
  これで130アカウントに新たに23区判定が付く。**負例は1件も誤って救われない**
- **行事名**は `event_series.canonical_name` ＋ `event_series_aliases.alias`（4文字以上）430件。
  「墨田区民納涼民踊大会」のように会場名では引けないものを拾う

### 8-3. 記録軸が「行ってきた報告」に狭すぎた（和太鼓お祭りCHの件）

内田さんから「和太鼓チャンネルさんは記録力でトップレベルのはずだが、なぜ入っていないか」
と指摘された。`@wadaikoch` の投稿は次の形で、**現地から実況している**。

> 今日の盆踊りは、東京スカイツリー『墨田区民納涼民踊大会』❣️ 始まりました✨ #盆踊り［写真］

75件の投稿のうち体験語（行った・踊った）を使っているのは**わずか2件**、文末の過去形も3件。
23区の盆踊りに47件言及しているのに記録の点数がほぼゼロだった。**148位**。

原因は2つあり、両方直す。

1. **体験語だけを手掛かりにしていた。** 現地にいることを示す言い方
   （今日の盆踊り／本日は／始まりました／まもなく／終わりました／なう／開催中／到着／
   出番／演奏中／ただいま）を追加する
2. **比率だけで測っていた。** 投稿100件のうち20件が記録なら0.2、20件のうち10件なら0.5で
   後者が勝つ。**たくさんの現場を回って記録する人ほど分母が増えて損をする**設計だった。
   記録軸の価値は「何件の現場を残したか」なので量の項を足す

```
# 濃さ
s  = 7 * smooth(onsite23, n, 0.08)     # 現地の記録（実況を含む）
s += 4 * smooth(photo23,  n, 0.10)     # 写真つきの現地記録
s += 4 * smooth(song,     n, 0.15)
s += 3 * smooth(place,    n, 0.15)     # 行事名か会場名を特定できる
# 量（20件で頭打ち）
s += 7 * min(log1p(onsite23) / log1p(20), 1.0)
s += 4 * min(log1p(song)     / log1p(20), 1.0)
s += 3 * min(distinct_post_days / 15, 1.0)
s -= 8 * listy_ratio
if recent_posts_seen == 0: s -= 3
if is_area_bot:            s -= 10
```

結果、`@wadaikoch` は **148位 → 13位**。同じ理由で沈んでいた
`@kaz0045`（写真28・曲34）39位→8位、`@fried_wakame`（曲25）36位→7位、
`@m125m8qgyhwuehs`（曲22）69位→16位、`@_masakari`（曲19）51位→18位 も浮上した。
教師データの2人はなつたろさん2位、宇佐美さん4位。負例は185位以下のまま。

### 8-4. 告知力の上限条件が緩かった

`bon23_count == 0` のときだけ上限8点をかけていたが、`@prtimes_etm`（企業リリース。
23区の盆踊りへの言及1件）が告知85位に残った。**`bon23_count <= 1` に強化**する。

## 9. 評論は軸にしない（2026-08-12 内田さんの判断）

内田さんの当初の整理は「未来告知／参加記録／評論」の3軸で、**軸ごとにベストメンバーを
選ぶ**（合計点は作らない）という設計だった。この方針は維持するが、**評論だけは軸として
成立しなかったので廃止する**。

実データで「盆踊りを主題にし、論の言葉と論点の言葉を伴う投稿」を数えると、
28,026件中**116投稿・101アカウント**しかない。しかも中身の多くが次のいずれかだった。

- 政治家の地域あいさつ（「地域の絆」「伝統を受け継ぐ」等の定型句。1人で22件書いている例も）
- 外国人・宗教をめぐる社会論争の中での言及
- ニュース記事（札幌で盆踊り会場が20年で半減）の拡散

これらを除いた残りは数人で、内田さんの評価も「全然ダメ」だった。

**代わりに、投稿単位のタグとして残す。** アカウントの選抜には使わず、
記事やニュースを書くときに評論的な投稿を後から探せる印を付けるだけにする。
維持コストはほぼゼロで、素材探しには使える。判定は上記の
主題構文 ＋ 論の言葉 ＋ 論点の言葉、政治家語・論争語の除外をそのまま使う。

したがって**名簿は「未来告知」と「参加記録」の2本**（第1版の告知/意見から名称と定義を変更）。
両方に載る人がいる前提は変わらない。

## 10. 自己紹介文で加点・減点する（2026-08-12 内田さんの提案）

内田さんの「自己紹介文に盆踊り・盆オドラーという決定的なキーワードがない人は減点すれば
良い加減になる」。実データでも強い信号だった。手元にある自己紹介428件のうち
**60%が盆踊り系の語を含み**、記録軸の上位はほぼ全員が該当する。

### 表記ゆれ（実データで確認した実際の形）

「盆オドラー」が最も一般的な名乗り（投稿本文で22件）。以下を判定語彙とする。

```
盆踊 | 盆おどり | 盆オドリ | ぼんおどり | ボンオドリ
盆オドラー | 盆踊ラー | 盆踊らー | 盆おどらー | ボンオドラー | ぼんおどらー | 盆ドラー | 盆らー
bon[- _]?odori | bon[- _]?odor(er|a)      ← BON ODORI / bonodori / BonOdori など英字も多い
音頭 | 民踊 | 民舞 | やぐら | 櫓 | 盆唄 | 盆太鼓
```

実例：「万年初心者🔰盆踊らーです」「黒衣の盆オドラー」「白馬の盆踊ラー」
「踊れる曲はまだ少ない初心者盆踊らー🏮」。変種として「盆キョドラー」「ギャル盆らー」もある。

### 組織アカウントは減点しない（重要）

町会・神社の公式アカウントは自己紹介に「盆踊り」と書かない。しかし告知源としては最重要。

- `@sunshinechoukai`「東池袋サンシャイン町会の公式アカウントです」（告知力4位）
- `@iri2choukai`「東京都中央区入船二丁目町会です」（告知力11位・出口へ2件届いた実績）

次の語があれば減点を免除する。

```
町会 | 自治会 | 商店会 | 商店街 | 振興組合 | 神社 | 寺 | 観光協会 | 青年部 | 婦人部
実行委員 | 保存会 | 連合会 | 公式 | 区役所 | 市役所 | まちづくり | 協議会
```

428件のうち組織語を含むのは87件、盆踊り語も組織語も無いのが107件。

### 自己紹介文をどう手に入れるか

**いまはどこにも保存されていない。** twitterapi.io のツイート応答には `author` が
含まれているのに、`_x_tweet_to_voice()` が `name` だけ拾って `description` を捨てている。
S3の生データ（`bon-odori-x-raw-posts`）にも `account` / `account_name` しか残っていない。

1. **今後の分**：`collect.py` が `author.description` を保存する（追加コストゼロ）。
   voices と生データの両方に入れる
2. **過去分**：評価対象の上位数百人だけ twitterapi.io のユーザー情報APIでまとめて取得する。
   1件$0.00001程度なので500人でも$0.005。日次の予算ガードの中で実行する
3. 手元の `data/x_candidate_accounts.json`（social graph 由来428件）は暫定的に使えるが、
   **負例14件は1件も入っていない**ので、これだけでは判定材料にならない

### 点の付け方

```
profile に盆踊り語あり            : announce +2 / record +3
profile に盆踊り語なし・組織語あり : 加点も減点もしない
profile に盆踊り語なし・組織語なし : announce -3 / record -4
profile 未取得                    : 加点も減点もしない（データ不足を減点にしない）
```

**未取得を減点にしないこと。** 取得できていない人が一律で沈むと、
取得順という無関係な理由で名簿が決まってしまう（満点タイのアルファベット順と同じ失敗）。

## 13. 判定できないことを減点にしない

### 13-1. 三値ではなく、証拠を独立に持つ（おとの指摘）

`tokyo23 / outside / unknown` の排他的三値にもしない。投稿ごとに次を**独立に**持つ。

```
has_tokyo23_evidence   # 区名・主要地名・会場マスタ・行事名マスタのいずれかが当たった
has_outside_evidence   # 都道府県名・政令市名・既知の都外地名が明示されている
```

- どちらも無い → unknown（**0点。減点しない**）
- 両方ある → mixed（東京と大阪を列挙した投稿など。東京側の証拠を消さない）

現行 `_x_is_tokyo23_text()` は都外語が1つでもあると即 False を返すため、
**mixed 投稿から東京側の証拠まで消えている**。ここを直す。

### 13-2. 行事名マスタを 23区判定へ接続する

S1b の実装は `is23 = _x_is_tokyo23_text(text) or has_place` で、**`has_event` が入っていない**。
「鉄砲洲納涼盆踊り」「大井どんたく夏まつり」のように行事名でしか23区と分からないものが漏れる。
`has_event` も `has_tokyo23_evidence` に含める。

### 13-3. 告知力の上限8点を撤廃する

第2版 8-4 で `bon23_count <= 1 && posts >= 5` に上限8点をかけたが、
**これは辞書の穴をそのまま減点に変える**。撤廃する。

`@prtimes_etm`（企業リリース）が上位に戻る懸念は、`is_area_bot`（高URL率・低体験率・
23区の盆踊りゼロ）と、13-4 の除外条件で受ける。**量だけで上位に来る問題は
「23区判定の欠如」ではなく「機械的発信であること」で捕まえる。**

### 13-4. 人を外す条件は「確実に黒」だけ

次のいずれかに当たるものだけを収集対象から外す。**unknown は外す理由にしない。**

1. `is_area_bot` が真（機械的発信で、23区の盆踊りを一度も書いていない）
2. **人が棚卸しで外したもの**（16節）
3. `manual_status` が `休止`

「30日間 23区の言及ゼロ」だけでは外さない。内田さんが `@mau3_141592`（盆踊り好きだが
関西中心）をNGとした判断は、**人が下したもの**として2の台帳に入る。機械が同じ判断を
自動で下すことは許さない。

### 13-5. 教師データ検査の足切りを撤廃する

`scripts/check_x_bonodorer_gold.py` の `rank()` にある
`bon23_count > 1 or gap_credits > 0` の `eligible` フィルタは、**順位以前にランキングから
除外している**。13-3 と同じ理由で撤廃し、全アカウントを順位付けしたうえで
「正例は上位50以内」「負例は上位180に入らない」を判定する。

## 14. 界隈の略称・通称をどこに持つか

役割を分ける（おとと合意）。

| 器 | 持つもの | 例 |
|---|---|---|
| 用語集v2 | 表記ゆれ・界隈語の正規化 | `DAIBON`→大盆踊り会（イベント別名）、神楽坂・木場・曙橋（地域語）、会場の通称 |

**⚠️ いまの `data/glossary_runtime.json` は `alias_map` と `role_terms` を出力しているが、
`_apply_glossary_runtime_to_x_config()` は `exclude_keywords` と `experience_keywords` しか
実動ロジックへマージしていない**（alias/role_terms は件数のメタデータになるだけ）。
**用語集へ DAIBON を足すだけでは23区判定は改善しない。型付き entity alias を判定器へ

未解決の語は unknown のまま減点せず、頻出かつ有用なものだけ用語候補へ送る。
なお local-judgment contract v1（E0/J0）は「候補を誰がどう裁定し履歴を残すか」の契約であって
地名解決器ではない。**地理判定を J0 に埋め込まず、未解決の重要語を term レーンへ送る
下流の裁定口として使う。**

## 15. 費用の削り方（優先順位）

`data/x_cost_ledger.json` のベースライン（2026-08-11、計 $0.7146/日）は次のとおり。

| 経路 | 費用 | 成果 |
|---|---|---|
| search（クエリ11本） | $0.264 | voices採用 660件 |
| whitelist（268人） | $0.1176 | voices採用 506件 |
| cohort_evidence（50人×2週間） | $0.3303 | 断片389・候補148検出・29昇格 |
| unattributed | $0.0027 | — |

**削る順序：**

1. **コホートの運用変更**（最大の$0.3303）。過去年の取りこぼし回収が済んだ後は
   毎日フル走査せず、(a)追加ハンドルの差分backfill (b)週次の漏れ回収 (c)通常の新着は
   whitelist 直読み、に分ける
2. **検索クエリの重複読み防止**。いまは毎回1ページ目から最大8ページを読み直し、
   保存時に既読URLを捨てているだけなので**既読分にも課金されている**。
   クエリ別の `since_time` watermark ＋ 新規URLが0のページで早期停止 ＋ クエリ別のページ上限
3. **名簿は削るより頻度を分ける**。手動優先＋告知上位＝毎日／記録上位＝週2〜3回／
   グレー・新規＝週1回／地域bot確定＝除外。**7〜14日の据え置き期間**を設けて
   1日で出入りしないようにする

**⚠️ 削減の効果を測るときは、必ず費用と成果を並べる。** ことは 2026-08-12 に、
有用性の定義を「盆踊り語＋23区」に狭めたまま測って、名簿削減の代償を43件と報告したが、
定義を広げると230件だった（5倍の過小評価）。**名簿の直読みの固有価値は
「検索クエリでは原理的に拾えない投稿」にあり、30日で125件（1日4.2件）。**
中身は「64'以前の東京音頭が踊れたのが嬉しかった」「〆は東京音頭か炭坑節というのが
以前は多かったが最近はダンシングヒーロー」といった盆踊りコミュニティの会話で、
**廃止した評論軸で拾いたかったものはここにある。** これを壊す削減はしない。

## 16. 棚卸し（人が決める部分）

内田さんの指示（2026-08-12）。

> 盆オドラーを列挙してもらい、私がみて不要と思われる人は除外していけば良いです。
> いわば棚卸しです。これは1年に１回くらいのペースでやってもいいかもしれないです。
> 除外した場合でも、何をもって除外したかは後で役立つかもしれないので（記録する）

- ことが 340人分の棚卸しシート（除外理由つき）を作成し、内田さんへ渡した
- 結果は `data/x_roster_exclusions.json` として持つ。**1件ごとに handle・理由・
  判断日・ひとことメモ**を残す
- **人が外したものを機械が復活させない。** 逆に、人が「優先／通常」と指定したものを
  機械が外さない（第1版 2-4 と同じ原則）
- 棚卸しは年1回を想定。次回に「前回なぜ外したか」を参照できることが目的

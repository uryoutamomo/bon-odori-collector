# X投稿の採点・材料抽出基準 v3.3

作成: 2026-08-16 / おと（Codex）

## 目的

投稿を捨てるためではなく、1回の通読で次の3種類の材料を本文どおりに記録する。

1. 投稿の優先度を表す1〜5点
2. 開催情報（5点だけE0レポート候補になる）
3. 曲claimと界隈語（点数に関係なく観測台帳へ残る）

既存イベント・曲マスタとの照合、正式名への修正、公開可否の決定はしない。迷った値を推測で埋めない。

## 採点（v3.2をそのまま継承）

採点は価値の大小ではなく、本文に何があるかを上から判定する。

```text
Q1. 盆踊りに触れているか？
    ├─ いいえ → 1点
    └─ はい   → Q2

Q2. 実在の、人が集まって踊る行事のことか？
    ├─ いいえ → 2点
    └─ はい   → Q3

Q3. 後でmaterialsとして使えるものが1つでもあるか？
    ├─ 特定行事の開催情報
    │   （日付・時刻・会場・主催のいずれか、中止・延期・時間変更） → 5点
    ├─ 特定行事の記録（行った・見た・踊った・出演した、会場の様子） → 4点
    ├─ 曲名・踊りの名前 → 4点
    ├─ 踊り方・歴史・由来・作法・界隈語・盆踊りへの意見 → 4点
    └─ どれもない（「今日は盆踊り」「盆踊り楽しみ」だけ） → 3点
```

| 点 | 意味 |
|---|---|
| 5 | 特定の実在行事の開催情報。E0レポート材料になり得る |
| 4 | 行事の記録、曲・踊り名、文化・作法・界隈語など再利用できる材料がある |
| 3 | 実在の盆踊りに触れるが、取り出せる材料がない |
| 2 | VR・ゲーム・キャラクター・比喩など、実在の人が集う行事ではない |
| 1 | 盆踊りに触れていない |

### 境界の約束

- **書き写せなくても5点は5点。** 会場が本文にない、相対日付を機械が拾えない、画像にしか情報がない等を
  理由に点数を下げない。その場合は `events` を付けず点数だけ返す。
- 5点は日付と会場の両方を要求しない。日付・時刻・会場・主催・中止延期等のどれかが具体的なら5点。
- 曲名は願望や思い出でも4点。「来年は炭坑節もやってほしい」も材料がある。
- 固有名詞がない盆踊り論も、歴史・由来・作法・界隈語など中身があれば4点。
- 行事名を挙げて「行く」「楽しみ」と言うだけなら3点。「行った・見た・踊った・出演した」なら4点。
- 出店・音響・DJ・出演の告知も、行事と日時または会場が読めれば5点。
- 花火大会・納涼祭は踊りに触れなければ1点。
- VRChat、ゲーム内、ぬいぐるみ、キャラクター音頭、比喩表現は2点。
- 返信・画像だけで本文から文脈が分からなければ推測せず2点。
- 地域では絶対に減点しない。23区外でも海外でも、同じ本文なら同じ点数。

v3.2で較正した目安は4点22.0%対29.3%（相対差25.0%）、5点16.0%対14.7%
（相対差8.3%）で、合格条件は4点・5点の構成比が判定者間で相対3割以内だった。
v3.3はこの採点分布を変えず、曲claimの意味と根拠を追加する改訂である。

点数は曲claimを捨てる条件ではない。点数と抽出は別作業なので、どの点数でも本文に曲材料があれば抽出する。
5点が過去日だった場合も採点と曲claimは残し、E0レポートだけ作られない。

## 回答JSON

```json
{
  "batch_id": "x_extraction_YYYYMMDD_NN",
  "scored_by": "oto",
  "results": [
    {
      "no": 1,
      "s": 5,
      "n": "公式の開催告知",
      "events": [
        {
          "event_name": "試験盆踊り",
          "date_start": "2026-08-20",
          "date_end": "2026-08-21",
          "venue_name": "試験公園",
          "ward": "足立区",
          "quote": "8月20日・21日に試験公園で試験盆踊りを開催",
          "song_claims": [
            {
              "song_name": "東京音頭",
              "claim_type": "announced",
              "evidence_quote": "曲目は東京音頭です"
            }
          ]
        }
      ],
      "observations": [],
      "glossary": []
    }
  ]
}
```

### 開催情報

- `events` は5点で検証可能な開催情報を書き写せるときだけ付ける。書き写せなくても点数は下げない。
  1投稿の複数行事は別要素にする。
- `venue_name`、`ward`、`quote` は本文から書き写す。正式名や住所を補わない。
- `event_name` だけは本文に固有名がなくても短い識別名を付けてよい。取り込み後は
  `event_name_in_text=false` として区別され、実在するE0系譜なしに曲の開催回解決へ使われない。
- `date_start` / `date_end` は本文にある日付だけ。年の推測はしない。
- `quote` は本文の連続した部分文字列にする。

### 曲claim

曲ごとに意味が違うため、`claim_type` は必ず各 `song_claims[]` に置く。

| claim_type | 本文が述べていること |
|---|---|
| `announced` | その開催回で流す予定・選曲済み |
| `observed` | その開催回で実際に流れた・踊った |
| `mentioned` | 願望・一般論・開催回不明の思い出など |
| `unknown` | 区別できない |

- `song_name` は本文表記のまま。
- `evidence_quote` は本文の連続した部分文字列で、必ずその `song_name` を含める。
- `announced` / `observed` は、引用と同じ行事要素から、その曲が当該行事の予定または実績だと読める場合だけ使う。
  行事が分からない「東京音頭を踊った」、単なる曲名列挙、事実種別を判別できない文は `unknown` にする。
- 同じ行事の「東京音頭を踊った」と「炭坑節もやってほしい」は、一方を `observed`、他方を
  `mentioned` として別claimにする。
- `events` に書けない曲材料は `observations` に置く。行事が不明なら `event_name: null` にする。
- 4点以下でも、行事文脈を本文から書き写せるときは `observations` に `event_date_start`、
  `event_date_end`、`venue_name`、`ward`、`event_quote` を付けてよい。別行事からコピーしない。

### 界隈語

`glossary` は本文に実際にある特徴的な語を文字列配列で返す。一般語を水増しせず、正式表記へ直さない。

## 禁止事項

- `events` / `observations` という置き場所から、告知・実測の意味を推測する。
- 本文にない曲名・行事名・日付・会場・引用を補う。
- 候補曲を既存曲・新曲だと判定する。
- 行事シリーズや開催回の同一性を判定する。
- 1つの不明なclaimを理由に、同じ投稿の他の材料を省略する。

詳細な保存・後方互換契約は [E0X-S v2.0](x-post-extraction-songs-v1.md) を参照する。

# レビューコンソール 次アクション型への改修設計

Updated: 2026-06-26 JST
署名: おと（Codex）

## 結論

レビューコンソールは、内部では既存のレビューソースを維持しつつ、管理者が見る入口を `ソース別` から `不足・次アクション別` へ寄せる。

目的は、拾ったデータを活用する流れを単純に見せること。

```text
拾ったデータ
  ↓
根拠として保存
  ↓
自動で不足チェック
  ↓
次アクション別レビューに出す
  ↓
使う / 要調査 / 保留 / 使わない
  ↓
採用後も品質チェックに戻る
```

## なぜ全部を1本に潰さないか

品質基準が違うため、内部データは分けたままにする。

- 2026年開催確定
- 過去年の実績
- 曲候補
- 根拠URL
- 会場
- 同一イベント性

ここを無理に1つの概念へまとめると、2026年確定と過去実績、曲候補と曲確定が混ざり、品質が落ちる。

ただし、画面上の入口は統一できる。

## 新しい見せ方

レビュー画面の左側に `次アクション` を追加する。

例:

- 日付確認待ち
- 曲候補待ち
- 根拠URL不足
- 会場確認待ち
- 同一イベント確認
- YouTube候補確認
- X/RSS確認
- その他

既存の `種類` と `ソース` は残すが、日常運用では `次アクション` を主入口にする。

## 内部モデル

各レビュー item に、次の派生フィールドを付ける。

```json
{
  "action_group": "song_research",
  "action_group_label": "曲候補待ち",
  "action_group_reason": "採用済み過去実績に曲候補がない"
}
```

これは元データを変更しない。`review_console.data.normalize_item()` で表示用に付与する。

## グルーピング初期案

| action_group | 表示 | 主な対象 |
| --- | --- | --- |
| `current_date` | 日付確認待ち | 登録済みイベント調査、予測日レビュー |
| `historical_date` | 過去実績日付再調査 | 採用済み過去実績の日付欠損 |
| `song_research` | 曲候補待ち | 採用済み過去実績の曲なし、曲実績由来の確認 |
| `source_url` | 根拠URL不足 | missing source URL、公式/準公式URL候補 |
| `venue` | 会場確認待ち | missing venue、曲実績由来の会場候補 |
| `identity` | 同一イベント確認 | 過去実績昇格候補、YouTube年次バックフィル |
| `youtube` | YouTube候補確認 | YouTube active/user confirmation |
| `social` | X/RSS確認 | X候補アカウント/投稿 |
| `other` | その他 | 上記に当てはまらないもの |

## 操作モデル

右側のボタンは、引き続き `反映ルート` として扱う。

- ボタンを押すと保存。
- `保存` ボタンは置かない。
- `解除` は残す。
- 反映ルートの細かい `apply_value` は、ユーザーが手入力しない。

## 品質ゲート

次のガードは維持する。

- 過去実績日がない候補は `過去実績として採用` できない。
- 2026年直接日付根拠がない候補は `2026年日程確認済みにする` できない。
- 曲候補がない採用済み過去実績は `曲候補待ち` に戻す。
- 日付・曜日がない採用済み過去実績は `過去実績日付再調査` に戻す。

## Phase

### Phase 1: 表示用 action_group を追加

- `normalize_item()` に `action_group` 系フィールドを追加。
- `/api/inventory` に `action_group_counts` を追加。
- `/api/items` で `action_group` フィルタを受ける。
- UIに `次アクション` フィルタを追加。

この段階では、既存のsource/domainフィルタはそのまま残す。

### Phase 2: ホームの導線を次アクションへ寄せる

- `今日やること` のリンク先を `source` ではなく `action_group` 中心にする。
- `曲候補待ち`、`日付確認待ち`、`根拠URL不足` を上位に出す。

### Phase 3: ソース表示を補助扱いにする

- 左サイドバーの主入口を `次アクション` にする。
- `ソース` は詳細フィルタとして残す。
- カードのチップも `次アクション` を目立たせる。

### Phase 4: 自動不足チェックの拡張

- 根拠URL弱い
- 同一イベント性が弱い
- 会場未確定
- 曲候補が過去年にしかない

などを item 側の `route_checks` と `action_group` に反映する。

## やらないこと

- Master RDB / Notion / 公開JSON をレビューコンソールから直接変更しない。
- 既存の個別 apply スクリプトをまとめて置き換えない。
- 2026年確定、過去実績、曲候補を1つの採用概念に潰さない。

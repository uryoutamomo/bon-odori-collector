# X盆踊ラー有益度ランキング 仮説検証メモ

作成: おと（Codex）  
日付: 2026-06-09

## 目的

Xの盆踊ラーを「有名さ」ではなく、盆踊りプロジェクトにとっての情報源価値でランクづけできるかを、既存の `data/voices.json` だけで低コスト検証した。

## 作成した検証データ

- `data/x_rank_validation_samples.json`
  - 投稿レビュー用サンプル80件
  - 高スコア50件 / 中位20件 / 低位10件
- `data/x_rank_validation_result.json`
  - おとによる一次レビュー結果
  - ラベル: `有益` / `微妙` / `不要`
- `data/x_account_rank_proposal.json`
  - 860アカウントの仮ランク案
  - 分布: S=9 / A=21 / B=93 / Candidate=723 / Probation=9 / Muted=5

## 一次レビュー結果

80投稿の内訳:

- 有益: 32
- 微妙: 14
- 不要: 34

スコア帯別:

- 高スコア50件: 有益31 / 微妙12 / 不要7
- 中位20件: 有益1 / 微妙2 / 不要17
- 低位10件: 不要10

## わかったこと

### H1: 高スコア投稿は有益か

おおむね有効。ただし、そのまま自動採用するには粗い。

高スコア50件のうち、有益は31件。微妙まで含めると43件なので、候補抽出には使える。一方で不要7件が混じったため、「高スコア=有益」とはまだ言えない。

### H2: 有益投稿を複数出すアカウントは今後も役に立つか

継続観測が必要だが、方向性は良い。1件だけ高得点のアカウントをS/Aにしない設計は妥当。

今回の仮ランクでは、1投稿だけ高得点のアカウントは `Candidate` 止まりにした。これにより「たまたま1件だけ拾えた人」を過大評価しにくくなった。

### H3: 中位スコアは昇格材料になるか

ほぼならない。

中位20件のうち有益は1件だけ。中位は「盆踊り語はあるが行動に効かない」投稿が多い。アカウント昇格には、原則として高スコア投稿か、人間が有益と見た投稿だけを使う方がよい。

### H4: 未来日程・会場名・写真/チラシ・リンクは裏取り成功率が高いか

近場・既知会場では高い。遠方や一般イベントでは過大評価が起きる。

不要判定になった高スコア例:

- 老人スポーツ大会の最後に盆踊り
- 見取り図盆踊り
- 演劇・お笑い・作品紹介に盆踊り語が入っただけ
- 書籍/曲/地域PRの文脈
- 遠方イベント告知

### H5: 参加レポ型は新規発見には弱いが、行く判断に役立つか

その通り。参加レポ型は「発見型」と別枠で扱うべき。

例: 混雑、踊りの輪、曲、盛り上がり、子どもの多さなどは、イベントDBの新規登録には直結しないが、行くかどうかの判断には効く。

## 次の調整方針

1. `S/A` は有益投稿の継続性で決める
   - 1投稿だけ高得点は `Candidate`
   - 有益投稿3件以上でA候補
   - 有益投稿8件以上かつ観測10件以上でS候補

2. スコアを2種類に分ける
   - `event_score`: 新規発見・裏取り向け
   - `voice_score`: 参加レポ・雰囲気判断向け

3. 近場・既知会場の重みを上げる
   - 中央区 / 台東区 / 墨田区 / 江東区 / 港区 / 品川区
   - 築地本願寺 / 浜町公園 / 晴海 / 神田明神 / 錦糸町 / 上野 など

4. 高スコア誤判定を減らす
   - 作品名・お笑い・演劇・書籍・曲発売・地域PRだけの投稿は減点
   - 「開催日+会場+盆踊り」でも遠方は `微妙` 扱い

5. 人間レビューの役割を残す
   - `promote` 候補は自動追加しない
   - 内田さんまたはおと/ことのレビュー後にXメンバーリストへ昇格する

## 現時点の結論

この方向は進めてよい。  
ただし、品質スコア1本ではなく「発見/裏取り」と「参加レポ」を分けてランクづけする必要がある。

## 通算・直近・品質スコア

2026-06-10 深夜、おと（Codex）が投稿品質のスコアを以下の3列に分けた。

- `通算品質スコア`: 蓄積済みの全投稿から見た投稿品質評価
- `直近品質スコア`: 直近30日の投稿から見た投稿品質評価
- `品質スコア`: 通算と直近を合わせた投稿品質評価

品質スコアの考え方:

- 直近投稿がない場合は通算品質スコアをそのまま使う。
- 直近投稿が少ない場合は、直近評価を20%程度から段階的に効かせる。
- 直近投稿が10件以上ある場合は、通算40% / 直近60%で見る。

Notionでは旧 `自動スコア`, `有益ランク数値`, `総合スコア`, `通算スコア`, `直近スコア`, `役割タグ` を削除し、`有益度スコア`, `品質スコア`, `通算品質スコア`, `直近品質スコア`, `直近投稿数`, `直近価値投稿数`, `得意タイプ` を追加した。`有益ランク` はカテゴリとして残し、`有益度スコア` は0-100の数字として同期する。

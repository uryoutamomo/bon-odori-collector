# LLM開催日予測・統合確度ポリシー

更新: 2026-08-18
署名: おと（Codex）

## 何を確率にするか

予測で公開する確度は1つだけとする。

> **そのイベント系列が対象年に開催され、かつ開催日が予測範囲と一致する確からしさ**

「開催される確率」と「その日である確率」を別々に表示したり、機械的に掛け合わせたりしない。
LLMが両方を含む1つの `joint_probability` を判断し、Pythonは根拠・日付計算・上限・語彙を検査する。
この数値は公式確認の代用ではない。対象年の主催者・自治体による直接発表が見つかった場合は、予測を続けず
`confirmed × confirmed` の確定経路へ送る。

## 公開する日本語

| 統合確度 | 日本語ラベル | 公開上の扱い |
| --- | --- | --- |
| 90〜99% | `ほぼ確実` | 具体日を予測表示できる |
| 75〜89% | `可能性が高い` | 具体日を予測表示できる |
| 55〜74% | `可能性あり` | 具体日を予測表示できる |
| 30〜54% | `参考予測` | 内部候補。通常公開しない |
| 0〜29% | `可能性は低い` | 日程未定として扱う |

予測日は必ず `予測` と `公式未確認` を併記する。`ほぼ確実` でも `開催確定` とは表示しない。

## LLMへ渡す根拠

- 凍結した `predicted_date_id` / `target_series_id` / イベント名 / 会場 / 対象年
- 有限のカレンダー規則とパラメータ
- 主催者または自治体が明示した例年規則とURL
- 規則に一致した過去年の日付・出典URL
- 当年の地域団体・会場・準公式カレンダー等の同日程シグナル
- 別日程・中止・休止・会場変更などの競合

LLMは、名称の似方だけで同一イベントと決めたり、URLの無い記憶を根拠に足したりしない。
日付は自由文だけで返さず、`calendar_rule` とISO日付を両方返す。

## 機械が守る上限

LLMは根拠の意味を読み、統合確度を選ぶ。Pythonは次の上限を越える判断を拒否する。

| 主催者等の明示規則 | 規則に一致した過去年 | 当年の同日程シグナル | 上限 |
| --- | ---: | --- | ---: |
| あり | 3年以上 | あり | 97% |
| あり | 3年以上 | なし | 93% |
| あり | 2年 | あり | 94% |
| あり | 2年 | なし | 89% |
| あり | 1年 | あり | 84% |
| なし | 4年以上 | あり | 92% |
| なし | 3年以上 | あり | 89% |
| なし | 4年以上 | なし | 87% |
| なし | 3年 | なし | 84% |
| なし | 2年 | あり | 82% |
| なし | 2年 | なし | 74% |

競合が1件でも未解消なら上限は49%。対象年の公式確認がある場合は予測契約自体を拒否する。
Pythonは、規則から対象年と各根拠年の日付を再計算し、すべて一致することも検査する。

## 亀有銀座商店街の判断例

`亀有銀座商店街納涼盆踊り大会` は次の組み合わせで判断する。

- 名称・会場・系列ID・既存予測IDが一致
- 主催者が「8月最後の土曜・日曜」という例年規則を案内
- 2023年 `8/26–27`、2024年 `8/24–25`、2025年 `8/30–31` が「8月最後の日曜で終わる週末」に一致
- 2026年の地域PTA情報が `8/29–30` を掲載
- 競合なし。ただし2026年の主催者による直接発表は未確認

このため、LLM判断は `joint_probability=0.95`、日本語は `ほぼ確実` とする。
状態は `predicted × rule_predicted` のままで、サイト表示は次の形になる。

> 予測：8/29〜8/30・ほぼ確実（公式未確認）

## 実行境界

`event_model.event_date_prediction_judgment` は、LLM JSONの構造、ID、会場、カレンダー規則、根拠URL、
統合確度の上限を検査し、指定した新しいSQLiteコピーにだけ反映する。元DBを同じパスで上書きできない。
本番RDBへの反映とサイト公開は、コピーでの整合性検査・公開JSON確認後に別途承認を取る。
